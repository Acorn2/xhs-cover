# 正文图片与整组图文流程

用于只做正文或封面加正文的需求。先读取 [正文模板](body-templates.md)，封面规则仍在 [Skill 入口](../SKILL.md)。本流程产出可执行的逐页文案、布局与图片提示词，用户要求图片时调用当前可用工具；本仓库不提供独立生图后端、自动排版合成器或发布功能。

## 内容先拆页

1. 从原文整理核心观点、事实、步骤、证据与限制条件。已有文件保留原件，页计划注明来源章节或段落，不凭空添加经验、数字、测评或效果。
2. 确定范围与平台。只要正文时不补封面；整组时单独记录封面方案，并明确总页数是否包含封面。总结页按需要安排，不强制添加目录页、过渡页或关注引导页。
3. 从八种正文主题中为整组推荐一种，按 [正文模板](body-templates.md) 的内容匹配与用户偏好选型。Hresh 未指定时优先考虑手绘讲义；明确指定新主题时直接采用，不重复问卷。选中新增五种主题时，读取 [扩展正文风格](body-styles-extended.md) 对应片段和视觉参考，确保字体、笔触、材质与解释图形都体现差异。
4. 按语义拆页：每页回答一个问题，每页有新增信息。保留操作顺序、条件和例外；避免同一段文字在封面、首张正文和总结重复堆叠。
5. 每页选择六种布局之一，填写逐字标题、正文、图注及必要来源。默认可从3–5张正文起步，内容不匹配时增减，不为凑页数补写空话；指定页数时优先满足，无法兼顾完整性与阅读时说明取舍。
6. 检查证据是否齐备。截图批注必须有真实截图；没有截图时明确缺口，改做概念解释页并标明示意性质，不能伪造按钮、数值或操作结果。

## 两平台分别安排正文

两平台的画布、比例和安全框读取 [platform-presets.json](platform-presets.json)。其中 `generationStrategy`、`titleChars`、`maxTitleLines` 和辅助标签数量描述封面起始策略，不能直接当成正文的信息限制。

| 决策 | 小红书图文正文起始建议 | 抖音图文正文起始建议 |
| --- | --- | --- |
| 每页任务 | 围绕可复用的结论、步骤或证据完整解释 | 围绕一个直接问题或操作动作推进 |
| 信息组织 | 一个主题下可有几条说明、截图批注与必要条件 | 短句为主，复杂说明拆成连续页，条件不能删掉 |
| 复杂内容 | 优先流程、对比、截图与清单 | 优先单一焦点，复杂双栏或关系图可拆开解释 |
| 连续性 | 让读者能按页复查和使用 | 保持逐页衔接，当前页清楚接续上一页的问题 |

这是可调整的设计建议，不是算法规律或上传限制。相同事实可以复用，所选主题也可以相同；分别记录每个平台的页计划与完整提示词，按各自的信息量和阅读路径独立生成，不通过裁切、改名或仅换平台名冒充另一版本。不为制造平台差异编造内容，用户锁定的文案保持原文。

## 每页记录与提示词

没有另行指定输出位置时，在当前任务工作区的 `output/<topic-slug>/` 下保存源文、`plan.md`、各平台的 `prompts/`、图片与 `review.md`，不依赖临时目录。已有文件保留，重复制作使用新版本目录。只做策划时记录未生成，不能虚构图片路径或检查状态。

`plan.md` 应包含范围、来源、平台、主题、封面是否单独制作，以及按顺序排列的页表：

| 字段 | 内容 |
| --- | --- |
| 页序 / ID | 只做正文时从正文01开始；整组明确封面与正文的阅读顺序 |
| 本页任务 | 用一句话写明要回答的问题及与前后页的关系 |
| 主题 / 布局 | 一个正文主题 ID及本页布局 ID |
| 逐字文案 | 标题、正文、注释和可选页码；锁定文字单独注明 |
| 依据与素材 | 原文段落、真实图片路径与用途；缺失项显式标记 |
| 构图与参考 | 信息层级、主视觉、参考仅用于主题还是实际证据 |
| 生成与检查 | 提示词路径，实际图片路径/尺寸、检查状态及未覆盖项 |

生图前每页保存一份独立、完整提示词，包含下列内容，不依赖“其余同上”：

```text
制作一张[目标平台]图文正文图片，任务是[本页问题]。
画布：[从该平台预设读取的比例与目标像素]；安全框：[从预设读取]。
主题：[正文主题ID及完整的主题视觉片段]。
布局：[布局ID、完整结构、阅读顺序和本页具体区块]。
只呈现下列文字，逐字准确，不添加新标题或装饰文字：
[标题、正文、注释及可选页码的完整原文与断行要求]
视觉素材：[真实素材路径、用途、保持不变的证据；无素材时写明概念图形]。
参考职责：[仅用于正文主题的样张，或无参考；真实截图另列为证据]。
一组正文统一字体层级、颜色和页码位置；本页布局按指定结构执行。
不出现人物、头像、手部、吉祥物或人物贴纸，不加账号、署名、Logo或水印。
不添加未经材料支持的数据、效果、评分或界面，不使用封面式巨字描边。
```

实际调用前填完所有字段，并把模板片段展开，删除不适用的可选内容。参考职责还须列明随包风格参考的路径及只借鉴的视觉特征；不提供参考图时写清主题特征，不虚构已传图。无人物是默认规则，用户明确要求改变时据其范围调整。

## 样张与生成

- 信息足够且用户要求直接生成时，先简述采用的主题、页数和布局后执行，不增加确认门槛。只要求提示词时止于提示词。
- 先生成一张能代表正文主题的页面，核对文字、层级与无人物要求，修正后再作为后续页的主题参考。优先选包含实际正文结构的页面，不用封面代替。
- 向后续页传递正文样张时，明确只参考字体气质、配色和线条，当前页仍使用自己的布局与文案。真实截图和主题参考分别列出，不把上一页的内容复制到新页。
- 封面人物母版和封面效果图不作为正文默认参考。只做正文时不要求上传人物照片，也不读取母版来生成新角色。
- 随包风格参考仅用于字体、笔触、用色和材质；参考中的人物、头像、英文内容、数字与原主题不进入新页。横向信息图按语义拆页或重排，不整图缩放、裁切或压缩成竖图。
- 用户要主题对照时，先用同一页、同一份逐字文案与信息结构制作所选主题候选，允许图形与材质表现差异；需要控制位置时固定具体区块。没有要求时只生成推荐主题，不自动生成8主题×6布局×2平台，也不因新增模板而默认生图。
- 中文文字较多时先精简或按语义拆页；若采用无字底图加文字合成方案，必须交付实际合成后的图片才能称为正文成品。当前工具不能完成时如实交付方案与缺口。
- 出错只修正对应页的提示词并另存新版；保持已通过页和源文，不静默覆盖。

## 示例：同一来源组织不同正文

下面是虚构的设计练习材料，不代表用户已实现的产品或效果：

> 整理资料时，先保留来源链接，再按主题归类，最后输出清单。输出清单中的每项仍应能回到来源核对。

范围：只做正文；主题：`body-clean`；无截图素材，不选择截图批注。两平台均独立策划，尚无生成图片。

| 平台 | 正文页 | 布局 | 标题与内容 |
| --- | --- | --- | --- |
| 小红书 | 01 | steps | 标题“资料整理的三个环节”；节点“保留来源链接 → 按主题归类 → 输出清单”；底部“清单中的每项都应能回到来源核对。” |
| 小红书 | 02 | checklist | 标题“清单交付前检查”；条目“来源链接是否保留？”“资料是否按主题归类？”“清单每项能否回到来源？” |
| 抖音 | 01 | explanation | 标题“整理先留来源”；主句“先保留来源链接”；说明“后续清单中的内容需要回到来源核对。” |
| 抖音 | 02 | steps | 标题“从资料到清单”；节点“保留来源 → 按主题归类 → 输出清单”；结尾“保留核对路径” |

小红书正文01的提示词示例（仅为提示词，无图片；执行时从 `xhs-note` 预设读取并附上画布与安全框数值，不在模板中维护坐标副本）：

> 制作一张小红书图文正文图片，解释资料整理的顺序。采用body-clean清爽文档主题：白底、深灰#202733中文无衬线正文，蓝色#2457D6重点，浅灰#F1F4F8辅助分区，细线、少量编号、充足留白。采用steps步骤流程布局：顶部左对齐短标题，中部三个节点自上而下排列，单向箭头连接，底部一条检查提醒。所有文字仅为：标题“资料整理的三个环节”；步骤1“保留来源链接”；步骤2“按主题归类”；步骤3“输出清单”；提醒“清单中的每项都应能回到来源核对。”。用抽象资料页、分类文件夹和清单物件示意，不画真实软件UI，不使用任何截图或参考图。中文清晰准确，节点与箭头不遮挡文字，所有关键内容远离画布边缘。不出现人物、头像、手部、吉祥物或人物贴纸；不加署名、Logo、水印、额外英文或虚构效果数据；不使用封面式巨字、描边或摄影背景。

## 验收与交付

- 原图逐字核对标题、正文、图注、数字和标点；关系图与流程图核对顺序、连线及方向。
- 检查默认无人物，素材真实，来源能回溯；页码与顺序一致，没有漏页、重复解释或条件丢失。
- 查看原图与手机阅读尺寸，确认正文清晰；缩略图用于层级检查，不能代替正文可读性检查。
- [展示检查](preview-workflow.md) 的清单可按阅读顺序列出各页，`style` 使用正文主题 ID，`importantRegions` 标注标题、正文块、批注或关键证据，无需脸部区域。几何报告不做OCR、主题识别或整组叙事验收。
- 图片生成后先记 `needs_review`；实际查看并修正后才能记 `reviewed`，注明平台上传展示尚未核验。只有计划或提示词时明确未生成，不能标为已适配。
- 最终成品按 [交付规则](final-delivery.md) 运行 `scripts/package_images.py`。页计划决定 `order` 与 `bodyPageCount`，不是生图先后或目录排序；修订替换同一页的路径。只做正文从第1张/正文01开始；整组从第1张/唯一封面开始，正文01是第2张。最终回复、顺序总览、统一编号文件和ZIP均使用同一份交付清单。
