# 图片完成后的发布文案

让读者拿到图片后可以接着填写发布页。这里只生成发布草稿；不登录平台、上传、定时或实际发布，也不保证传播结果。所有公开字段遵守 [公开内容边界](../SKILL.md#公开内容边界不展示网址不刻意引导)：不展示网址、域名、二维码、联系方式，不刻意引导访问、私信、评论领取或关注互动。

## 何时执行

- 封面＋正文的整组图片完成并复核后，默认补齐对应平台的发布标题、一段简短正文和标签，再一起交付，不等用户另问一次。
- 用户明确只要图片时跳过全部发布文案，打包使用 `--images-only`。用户明确只需某些发布字段时按指定范围提供。
- 只做封面、只做正文、提示词或风格比较时不默认扩张任务；用户要求补发布正文、标题或标签时，直接复用当前资料和图片，不重新生成图片。
- 用户只补某个字段时只改该字段，已选标题、图片和标签保持原样。已有其他工具或人工确认的文案检查公开内容边界后复用，不重新访谈，不要求安装其他 Skill；发现既有图片有网址或引导时指出具体页和缺口，不因本次只补文案而声称整组已通过复核，也不擅自重新生图。

## 内容判断

1. 从源文、页计划和最终图片确认这篇内容讲什么、给谁看、有什么可获得的东西。区分产品本身的能力与这组图片实际覆盖的内容；标题提到的规矩、步骤、对比或教程，必须能在正文图片或原稿中兑现。
2. 发布标题是发布页输入框的文字，独立于封面图中的大字。封面已说清“我做了什么”时，发布标题可补一个痛点、具体用法、好奇问题或鲜明判断；不因补标题而自动改图。用户锁定的封面文字和发布标题分别保留。
3. 默认提供3个实质不同的候选：1个推荐、2个备选。优先比较“具体困境”“值得知道的判断或悬念”“真实创作过程或资源价值”，不靠替换“太绝了、居然、神器”等词凑候选。每条给实际字符数和一句简短看点；推荐理由比较读者想点开的原因，不用自拟分数或点击率。
4. 用户已锁定发布标题时默认不另写备选。不要添加未经支持的经历、实测数量、收入、效率倍数、免费生图或效果承诺。“开源”与“生图能力及额度”分开判断，不把开源 Skill 说成附赠本地模型。
5. 推荐标题、备选、发布正文、标签及按需提供的评论草稿均不附网址、域名或联系方式；不加“主页有入口”“评论关键词领取”“私信发你”等收尾或用标签变相引导。用结论、适用情境或内容本身自然结束，不默认补互动问题。确需署源时用名称、文献标题或年份，具体链接只记在内部 `work.md`；不把研究来源列表直接粘贴成发布稿。

## 平台与字符

| 平台 | 发布标题 | 标签起点 |
| --- | --- | --- |
| 小红书图文 `xhs-note` | 具体问题、用途或判断；本 Skill 采用不超过20字符的编辑预算 | 默认6–8个相关标签，可按内容增减 |
| 抖音图文 `douyin-note` | 一句短钩子，突出一个直接问题或结果；记录实际字符数 | 少量直接相关的主题、场景与人群词，不堆标签 |

长度按 Python `len(text)` 计算，标点、空格和英文均计入。这是本 Skill 的编辑预设，不声称是已核实的平台上传上限，也不复用封面预设的 `titleChars`。用户明确锁定超过预算的标题时保留原文、记录长度提醒，不自动截断。脚本不为抖音写死未经核验的上传限制。

两个平台分别写发布文案，只交付选定平台的版本。

## 简短发布正文

写一段能直接粘贴到发帖正文框的文字，默认约60–120字，可随内容和用户要求调整。首句说清这组图解决的具体问题或讲的事，再用一两句交代关键做法、例子或结论。以源文和最终图片为依据，优先提炼有用的信息，避免逐页复述图中文字。用具体发现或适用场景收尾，标签单列。小红书侧重读者能拿走的方法，抖音图文首句直接点出问题或结果。

## 标签

从主题词、具体任务/场景词、目标读者词和有依据的产品/技术词中选择。优先相关性，避免同义重复；不把发布页自动推荐的生活类话题直接套到技术内容上。

- 输入清单中每个标签是独立字符串，可带一个前导 `#`；脚本统一保存为无 `#` 的去重词，再输出可复制的 `#话题` 一行。
- 不含空标签、内嵌 `#`、空格或大小写重复词。标签数量是编辑建议，不是平台算法规则。
- 未查询就不称为“热词”“热榜话题”或“官方活动”；纯文本建议不等于已在平台绑定成功。不用无关人物、竞品或泛生活标签凑流量。

## 研究与边界

已有源文和图片足够时直接写。用户要求找类似项目、核实某项能力，或确实缺少定位信息时再做轻量检索；优先实际仓库 README 和相关 Skill/规则文件。小红书登录、Top10样本采集和外部写作工具不是本流程的前置条件。

GitHub 方法参考可从以下公开项目开始：

- [xhs-title-skill / SKILL.md](https://github.com/ren644/xhs-title-skill/blob/main/SKILL.md)：参考场景、痛点、悬念等不同切口和逐词打磨，不沿用其未核实的效果宣称或夸大数字。
- [xhs-notes-skill / function_playbook.md](https://github.com/azlll/xhs-notes-skill/blob/main/references/function_playbook.md)：参考按任务、场景和人群组织标签，以及只补所需字段的工作方式。

以上相关文件已于2026-10-22实际读取，是方法线索，不能作为“标题已验证会爆”的证据。不复制或执行外部项目代码；只有用户要求研究时才补相应来源，链接放在内部研究记录，不进入发布字段，不强制每次联网。工具不可用时如实说明研究缺口并继续基于现有材料写草稿。

## 写入交付清单

默认将推荐标题、备选、简短正文和标签填写到 [最终交付清单](final-delivery.md) 的 `publication`，正文使用 `publication.body`。`pages[].title` 继续记录图片内预期标题，不挪作发布标题。写入前逐项检查公开内容边界；`titleLocked` 仅表示标题锁定，不免除此检查，冲突时按入口规则给替代草稿。脚本校验并输出 `publication.md` 与HTML可复制区，只检查结构和编辑预算，不识别网址或引导语义，不能代替人工文案复核。不额外复制为JSON和交付Markdown。只补文案时用 `--update-publication` 更新同一交付目录，不复制或重新生成图片；ZIP仅按需生成且只含最终图片。

最终回复先列发布顺序与唯一封面，再给可复制的推荐标题、简短正文、标签、两条备选及简短看点，并链接完整交付入口。只补某个字段时遵循用户指定的范围。
