# 小红书图文与抖音图文：生成前的策略

当前仅支持 `xhs-note` 与 `douyin-note`。两者都使用3:4、1080×1440设计预设；平台差异由生成前的内容包装和构图决定。数据以 [platform-presets.json](platform-presets.json) 为准，特别是每个平台的 `generationStrategy`。

本页的标题、辅助标签与人物策略用于封面。正文使用同一画布和安全框，但独立选择主题、拆页和布局，详见 [正文流程](body-images.md) 与 [正文模板](body-templates.md)；不把封面的信息预算当作正文上限，不默认继承人物或封面配色。

| 决策 | 小红书图文 | 抖音图文 |
| --- | --- | --- |
| 首先表达 | 主题及能获得什么具体帮助 | 一个明确问题、反差或场景卖点 |
| 标题 | 保留主题/问题与用途关键词，建议4–12字 | 更短的单一钩子，建议4–10字 |
| 辅助信息 | 可用最多3条短步骤、标签或真实证据 | 优先0–1条强化短句，其余进入正文或后续图片 |
| 视觉锚点 | 标题、人物/产品和证据形成清楚层级 | 放大一个人物、产品或结果图，减少分散小卡片 |
| 同一04教程风 | 可以呈现三个短步骤 | 优先呈现问题与最终产物，步骤不挤进封面 |
| 生图动作 | 完整提示词，独立生成 | 另一份完整提示词，独立生成 |
| 生图后检查 | 文字、主体、边距与缩略图 | 文字、主体、边距与缩略图 |

这是本库的起始设计策略，不是平台唯一审美或算法规律。用户有不同内容定位时可以调整标签数量、文字长度与表达强度，不为追求区别而制造夸张承诺。

## 事实与复用

例如内容已说明“收集资料、按主题归类、输出清单”三个环节，小红书可用“AI资料整理流程”，辅以“收集 / 归类 / 输出”；抖音可用“资料一多就乱？”，只保留“整理成清单”作强化，集中呈现资料与清单的概念关系。

不添加效率翻倍、全自动、实测或零基础等材料未支持的结论。材料没有数字时不硬编榜单数量；用户锁定标题时不改文案，通过画面构图和辅助信息分配体现区别。

人物身份、品牌颜色、字体气质与真实产品素材可以共享；最终画面需分别组织。01–08及09–12都先服从平台策略，不将“极简”“科技”等风格和平台绑定。

人物可使用真人或[固定虚拟人物](virtual-character.md)。虚拟人物共用同一母版与画风，小红书可由人物指向少量步骤或证据；抖音在人物与产品之间选择一个主视觉，再决定人物大小与动作。不要求真人照片，不把同一张人物封面裁成两个平台版本。

## 生图执行

1. 从同一内容提取事实与目标受众。
2. 为每个平台分别写出目标、钩子、主标题、辅助文字、视觉焦点及布局。
3. 组合风格，明确参考图用途，输出各自完整提示词。
4. 用户要求生图时按两份提示词分别生成，不裁切小红书图片充当抖音版。
5. 最后查看原图和小尺寸；不清楚时修改相应平台的提示词并修正或重生。

平台名替换、改文件名、调整像素或事后裁剪不能代替第2–4步。完整例子见 [两平台生成策略对照](multi-platform-example.md)。

## 比例与检查边界

3:4、目标像素、标题长度和5%基础边距都是设计预设。两平台均采用相同基础安全框，不把未核实的视频按钮区、字幕区或方形裁切强加给图文。预览只辅助检查已有图片，不产出平台策略、不自动识别人脸，也不代表平台真实截图。生图工具无法精确输出目标像素时报告实际尺寸，不拉伸人物或文字。

[小红书电商学习中心的场景化笔记课程](https://school.xiaohongshu.com/lesson/normal/af0fe7e97bb0433fac9da5d1df52b07f)包含图文3:4建议；其上下文不能外推成所有笔记的硬性规格。本库未据此声称点击率结果；抖音图文的设计预设与策略沿用用户提供方向，上传前仍需核对当前发布入口。

抖音视频、公众号、视频号和朋友圈暂不纳入。旧五版位裁切演示保留在仓库归档目录，不作为当前能力。
