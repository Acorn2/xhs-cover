# 小红书 / 抖音封面与正文图 Skill

保留原名称 `atutun-xhs-cover`，兼容既有调用。将内容策划、视觉风格、平台版位分开处理：**同一份事实，按两个平台分别制定生成策略和构图；封面与正文独立选择视觉模板**。当前只支持图文，两个预设都为3:4；不同策略须在生图前进入提示词。

## 先确定制作范围

| 范围 | 处理方式 |
| --- | --- |
| 只做封面 | 沿用下方12种封面风格与人物规则 |
| 只做正文 | 读取 [正文流程](references/body-images.md) 与 [正文模板](references/body-templates.md)，不额外生成封面 |
| 整组图文 | 封面与正文分别选模板；正文先拆页，再为每页选布局并生成 |
| 补发布文案 | 复用已有资料和最终图片，读取[发布文案流程](references/publication-copy.md)，不重新生图 |

只提到“封面”或旧调用没有说明制作范围时，保持只做封面；明确说“正文图片/内容卡片”时按正文处理，明确说“整组/封面加正文”时制作整组。上下文已确定的范围直接沿用；泛称“做图”且无上下文时说明按封面开始，不自动扩张为整组。页数不足以承载内容时说明取舍，不填充空洞页面。

**正文默认无人物、头像、吉祥物或人物贴纸，包括总结页。** 正文独立选择主题，不继承封面人物母版、配色、摄影背景、大字或描边效果。一组正文统一主题，各页按内容选择布局；无需与封面同模板或同配色。除非用户明确要求改变，不向正文生图传入人物母版或封面效果参考。

正文未指定风格时默认采用 `body-sketch` 手绘讲义，用户明确选择其他主题时直接采用。正文八种主题的入口见 [正文模板](references/body-templates.md)。选中清透双色文艺印刷、颗粒蜡笔插画、清爽数字手绘注解、撕纸手绘拼贴或黑板粉笔时，按需读取 [扩展正文风格](references/body-styles-extended.md) 的对应段落和随包参考。参考中的人物、英文文案和数字不进入新图，横图必须按3:4重新设计。手绘讲义样张已随包保存，用于默认主题参考，不覆盖用户明确选型。

## 公开内容边界：不展示网址，不刻意引导

适用于所有风格、两个平台的封面、正文图（含总结页、页脚和图注），以及配套发布标题、备选、发布正文、标签和用户要求的评论草稿。发布内容直接讲清观点、过程、用法与结果，不把获取完整信息留给跳转或互动。

- 不展示网址、裸域名、短链、仓库地址、邮箱、手机号、微信号等联系方式或二维码；不以品牌落款、来源标注、资源清单、代码片段或截图为由带入。也不使用拆字、谐音、空格、变形域名等方式变相呈现。
- 不主动加入“扫码体验”“去官网/主页”“链接在简介/置顶评论”“私信领取”“评论关键词发资料”“加我获取”等引流话术。不用“想要吗”“懂的都懂”等暗示替代，也不自动追加求关注、点赞、收藏、转发或留言的收尾。
- 产品、项目或工具名称可为解释内容自然出现；正常的功能操作、方法步骤和结论继续保留。不把产品介绍改成访问、下载、联系或领取入口，不为增加互动刻意藏起步骤或答案。总结页用本篇结论、适用条件或检查项自然结束。
- 生图前检查源文和素材：保留原件；另做展示用截图，裁掉无关地址栏、链接区和二维码，必要时局部遮挡并记录处理，不能改动被说明的功能、数值或操作结果。风格参考中的网址与引导文案一律不继承；素材无法处理时换用其他证据或布局，不伪造界面。
- 来源链接和核验依据仅保存在内部 `work.md`，图片需要署源时用来源名称、文献标题或年份。Skill文档中的参考链接、内部提示词记录及本地交付文件链接不属于发布文案，不复制到图片或发布字段中。
- 锁定文案若与本节冲突，指出冲突并给出无网址、无引导的替代草稿；不擅自把替代稿记为已确认，也不直接沿用冲突原文生图或作为发布稿交付。

每张最终生图提示词都明确写入“不出现网址、域名、二维码、联系方式或引流/互动引导文案”。生成后逐张查看文字、截图、背景和边角，配套文案逐项检查；未通过时修正并复核，不能标为 `reviewed` 或 `final`。这是一致的创作约束，不据单张违规通知推断具体触发点，也不承诺平台审核通过。

## Hresh 封面人物要求

**为 Hresh赫什制作的小红书图文、抖音图文封面，01–12所有风格都必须出现已确认的虚拟人物。仅用户明确要求无人物或替换角色时例外。** 先读取 [固定虚拟人物](references/virtual-character.md)，再制定平台策略与选择风格；不能因极简、产品/截图主视觉、单一焦点或信息密度自行省略人物。产品或场景可以是主视觉，人物仍须在原图和缩略图中清楚可辨。

“不露脸”“不用真人照片”“产品为主”“封面无字”不等于无虚拟人物。“纯文字大字”“文字大标题”等描述只约束文字表现，不能据此推断整张封面无人物；仍按默认人物和已确认效果制作。只有用户明确限定整个封面不得有人物，例如“封面不要人物”“整张封面只要文字”，或明确要求替换角色时，才按该范围执行，并在工作记录中保留原始指令；不能把AI自行选择无人物记为用户例外。其他用户不自动套用 Hresh 人物或品牌。正文仍按上方默认无人物规则执行。

沿用Hresh人物的封面生图时，必须实际传入 [黑色T恤人物母版](assets/hresh-character-black-tee.png)与[已确认效果参考](assets/hresh-cover-approved.png)，分别控制身份和视觉层级；只写文件名不算传图。交付前目视确认人物存在、身份一致且清楚可辨；没有用户明确例外而缺人物、换成其他角色，或尚未复核时，不得标记 `reviewed` 或 `final`。明确例外及复核证据随页计划记入工作记录，详见 [最终交付规则](references/final-delivery.md)。

**Hresh封面标题字形和字效是强制标准。** 除用户明确要求不同标题风格或无字封面外，01–12均以已确认效果图中的粗壮、紧凑展示字形和黑色厚字效、细白外边、硬阴影为准；蓝黄配色只是其中一项。无论标题由生图还是后期合成制作，都必须用效果图实际控制标题设计，普通系统字体叠描边不能自动视为符合标准。逐字检查标题后，将成品标题与参考图并排比较字重、字形、比例、字距、描边和阴影，并看原图与缩略图；任何一项不符合或未核对，必须修正，不能填 `reviewed` / `final` 或交付。使用版本2交付清单记录此项检查，具体要求见 [当前封面标准](references/virtual-character.md#标题字形与字效强制验收) 和 [最终交付规则](references/final-delivery.md)。

## 输入与默认

从用户已有消息提取五类信息，不强制逐项问答：

| 输入 | 如何处理 |
| --- | --- |
| 内容 | 文章、选题、讲稿或产品资料；提取核心观点、对象和可用事实，缺内容时才补问 |
| 平台 | 小红书图文、抖音图文或两者；未指定时说明默认小红书图文，仅写“抖音”时说明按图文处理 |
| 主体 | Hresh封面按上方人物要求保留虚拟人物，再确定产品/软件、场景或图解的主次；其他用户可选真人、虚拟人物或无人物。正文以内容、截图或图解为主体，不询问人物身份 |
| 素材 | 列明每张图用于人物身份、风格、产品证据或背景；一图多用途时分别说明 |
| 偏好 | 制作范围、页数、封面风格、正文主题/布局、固定文案；封面与正文偏好分别记录，未指定的按内容推荐 |

只询问会实质改变结果的缺失信息，尽量一次收齐；样式偏好用2–3个具体选项即可。用户指定“直接生成”且信息足够时执行，不要求再选一次标题或风格。只有用户选择真人且需要保持身份、又没有参考照时才要求补图；选择虚拟人物或无人物时不索要真人照片，不凭空推测用户的真实长相。

以下人物与 Hresh 配色规则仅用于封面。Hresh封面及其他用户选择虚拟人物时，读取 [固定虚拟人物](references/virtual-character.md)，优先使用用户已确认的母版；没有母版时才确认新角色方向。Hresh默认使用随 Skill 保存的 [黑色T恤人物母版](assets/hresh-character-black-tee.png)，无需真人参考照；人物身份与服装分开控制，用户要求换装时保持脸型、发型和画风，不必保留旧衣服。选择产品或场景主视觉不取消上方人物要求。

Hresh 的默认效果以[用户已确认封面](assets/hresh-cover-approved.png)为准：黑色T恤手绘人物、亮蓝与明黄标题、低饱和背景、无账号名称。生成时同时提供人物母版与效果参考，分别控制身份和视觉层级；详细分工及可复用提示词见[当前封面标准](references/virtual-character.md#当前封面标准)。旧蓝黄服装示例只用于历史构图参考，不作为当前配色默认值。

用户锁定的标题在符合上方公开内容边界时不改写。允许按平台改写时，从同一事实生成不同短标题，不新增测评次数、成绩、收入、效果、经历或“零基础”等无依据承诺。有其它内容包装工具产出的标题或 brief，检查公开内容边界后复用已确认内容，不重跑整套访谈，不要求安装其它 Skill。

封面与正文默认不添加账号名称、署名、账号水印或个人品牌Logo；人物身份和品牌配色只用于视觉一致性，不等于要把“Hresh赫什”等名称写在图片上。只有用户明确要求添加时才纳入图片文案。

## 生图前先确定平台策略

以下标题与辅助标签策略用于封面。正文只复用同一平台预设的画布与安全框，按 [正文流程](references/body-images.md) 分配逐页信息；不把封面的 `titleChars`、`maxTitleLines` 或 `supportingLabels` 当作正文信息上限。

读取 [两平台生成策略](references/platform-adaptation.md) 和 [预设数据](references/platform-presets.json)，当前仅有两个有效 ID：

| 平台 | 比例与目标像素 | 生成重点 |
| --- | --- | --- |
| `xhs-note` 小红书图文 | 3:4，1080×1440 | 主题与实用价值清楚，可组织少量步骤、清单或证据 |
| `douyin-note` 抖音图文 | 3:4，1080×1440 | 一个短钩子、一个主体焦点，减少辅助字与小卡片 |

先读取对应预设的 `generationStrategy`，分别确定目标、标题表达、辅助信息预算与视觉锚点，再选择风格。辅助标签数量和标题长度是可按内容调整的设计建议，不是上传限制或平台算法规律。比例相同也不能只替换平台名，或裁切小红书成品后称为抖音版。

两平台共用通用安全边距；未取得实际界面资料时不硬套视频右侧按钮、底部字幕或方形裁切。生图工具无法精确输出目标像素时报告实际尺寸，不拉伸人物或文字。

抖音视频、公众号、视频号和朋友圈不在当前范围，不能默认生成这些版本。用户明确要求时说明需另行扩展当前范围。**优先级：用户明确要求 → 制作范围及页面职责 → Hresh封面人物要求 → 对应平台的封面/正文策略 → 主题与布局。**

## 选择封面视觉风格

先按内容与目标版位推荐一个主方案，必要时给一个取舍清楚的备选；除非用户要求浏览完整库，不一次抛出12个选择，也不默认生成12款×所有平台。

| 编号 | 风格 | 选择依据 |
| --- | --- | --- |
| 01 | 爆款大字压顶风 | 强标题、人物反应、经验与教程入口 |
| 02 | 巨字拆分冲击风 | 少量核心词、概念或能力展示 |
| 03 | 小白科普问答风 | “是什么/如何理解”、疑问与解释 |
| 04 | 教程清单风 | 有真实步骤、安装部署或上手 |
| 05 | 产品测评榜单风 | 有产品比较证据或明确数量 |
| 06 | 种草推荐风 | 亲切推荐、资源与生活化工具分享 |
| 07 | 贴纸拼贴入门风 | 多素材、工具组合与入门路径 |
| 08 | 黑底效率工作流风 | 工作流、自动化、软件组合 |
| 09 | 极简知识专栏风 | 知识解释、方法论与系列识别 |
| 10 | 专业科技测评风 | 产品/界面证据为主、理性对比 |
| 11 | 真实生活记录风 | 真人经历与真实环境，少量文字 |
| 12 | 数据分析报告风 | 有可核查数据的分析；无数据则改为定性结构 |

选择01–08时读取 [阿囤囤视觉库](references/styles-atutun.md)，选择09–12时读取 [扩展视觉库](references/styles-extended.md)。未指定品牌时，01–08使用原浅黄/白色基础模板；Hresh 方案先以已确认标准替换模板中的颜色、衣着和背景描述，再组合各模板的构图，不能同时保留新旧两套要求。人物保留母版的手绘画风，背景可为摄影场景。09–12不强制震惊表情或高密度，但 Hresh 标题仍须遵守上方已确认字形与字效要求。品牌色来自用户，不自动把某个平台绑定某种颜色，也不默认植入 Hresh 品牌或广告。

## 输出封面方案与提示词

每个选中版位分别输出：

1. 平台 ID、生成目标、核心钩子、辅助信息预算、视觉焦点，再给出画布比例、目标像素、风格编号及理由。
2. 主标题、可选副标题/清单，及关键数字或效果对应的内容依据。
3. 人物/产品、背景、标题与装饰的位置和遮挡关系，含安全区与预览方式。Hresh封面须明确人物位置与动作；采用例外时列出用户明确指令。
4. 参考图用途、一个可直接使用的最终提示词、文字生成策略；虚拟人物须列出母版路径、固定特征与可变动作。Hresh 方案还须列出已确认效果图的路径及其仅用于标题配色、背景层次和材质关系的职责。
5. 若有图片，列出实际路径、实际尺寸和检查状态；没有图片时明确当前交付是方案/提示词。

最终提示词顺序：目标平台和生成策略 → 3:4比例 → 参考职责 → 具体场景 → 主体动作或产品证据 → 标题原文与字效 → 按信息预算选择的装饰 → 安全区及禁止无关文字。末尾明确写入上方公开内容边界的禁止项；填入所有适用占位符，删除不适用的可选项。

两平台复用人物身份、品牌色与真实素材，分别安排标题、主体与证据。例如同一04教程风，小红书可展示三个短步骤，抖音封面优先保留一个问题和最终产物，其余步骤放进正文或后续图片。用户锁定同一标题时保留原文，通过主体比例、辅助信息与位置体现策略区别，不能悄悄改字。

## 图片生成、文字与复核

- 用户只要提示词时止于提示词。用户要求生图时使用当前环境可用的图片工具，仅生成所选方案；不要求固定服务或密钥。
- 选中两平台时写两份最终提示词并分别生成原图；不得将同一图片的裁切、缩放或平台标签变化当成两个版本。只有用户授权生图才生成，不默认制作12种风格×两平台的全部组合。
- 中文短标题、精简正文可直接生图，再逐字检查，包括标点、数字与箭头方向。文字多时先按语义拆页；需要编辑时规划无字底图与独立文案/位置记录，交给可用合成工具。当前仓库不提供图层合成器，不能把带字 PNG 称为可编辑文字层，也不能只交底图便声称正文成品完成。
- 正文先生成并检查一张代表性正文样张，再将其作为后续页的主题参考；正文样张不锁定其他页的布局。封面不作为正文默认参考，失败单页单独修正，不重复生成已通过页面。缺少正文内容时先取得内容，不编造正文成品或视觉验收结果。
- 生图后检查3:4原图、标题准确性、主体、安全边距与小尺寸可读性。可用 [展示检查](references/preview-workflow.md) 和 `scripts/preview_covers.py` 生成离线 HTML 与 JSON；这是验收辅助，不负责生成平台策略或最终图片。
- 按上方公开内容边界逐张核对原图和截图区域，检查网址、域名、二维码、联系方式与引导话术；不能只检查页计划或提示词。来源网址留在内部记录，配套文案同样复核。
- Hresh封面先核对人物是否实际出现；仅用户明确例外时可省略或替换。虚拟人物再对照母版检查脸型、发型、服装配色、画风、表情与手部，并检查缩略图中是否清楚可辨；确认没有写实化、幼化或换成其他角色。未通过须修正并复核，不得进入最终清单。人物插画与真实产品截图分别标明用途，不把插画当作使用经历或测评证据。
- 当前默认预览只做3:4整图与缩略图，不做跨比例裁切或预设视频界面遮挡。原图比例不匹配或关键标题/脸部出界时应重排或重生，检查程序不替代修改。
- 缺少重要区域标注或尚未查看预览时，不能声称自动识别文字、脸部或“全部适配通过”。结构检查不替代美观、事实和平台上传检查。
- 交付时记录 `preview_only / needs_review / reviewed` 状态与未覆盖项；只有实际查看并修正过的结果才能说明“已目视复核”，不自动发布。

## 最终图片按阅读顺序交付

封面与正文整组图片完成并复核后，默认读取 [发布文案流程](references/publication-copy.md)，按已选平台提供1个推荐发布标题、2个不同切口的备选、一段简短发布正文及相关标签；记录字符数和简短看点，不等用户另问。发布标题独立于封面大字，必须由当前内容承接；锁定稿检查公开内容边界后复用，不承诺“必爆”，不执行发布。只要图片、提示词或风格候选时遵循用户范围；只做封面或只做正文不默认追加发布文案。

交付实际成品时必须读取 [最终交付规则](references/final-delivery.md)，人工复核后执行 `scripts/package_images.py`，不要手工扫描生成目录打包。每个平台分别填写明确的页序、封面/正文职责、计划正文数量与选定版本；整组恰好一张封面且排第一，只做正文时不得加封面。重试与修图替换原逻辑页，不增加交付页数。新做整组时在 `publication` 中填写标题、简短发布正文和标签，脚本仍兼容已有的标题与标签清单；仅用户明确只要图片时使用 `--images-only`。

默认每个平台只交付一份统一编号图片、`index.html` 和有文案时的 `publication.md`；ZIP按需用 `--zip` 生成，不输出重复的README、JSON或Markdown顺序清单。页计划、来源、提示词和复核记录集中在 `.tmp/<topic-slug>/work.md`，生成修订、交付输入与检查报告留在同一工作目录；用户要求可复现资料时才整理 `process/`。详见最终交付规则，不额外复制源文、原图或提示词。

最终回复以脚本校验并输出的页序为准，列清“第1张·封面、第2张·正文01……”及总张数，链接按序总览；有ZIP时才链接原图包，并直接给出可复制发布标题、正文、标签与备选。补发布文案时使用 `--update-publication` 更新原交付目录，不另建一套图片。内联展示每张只列一个最终版本。生图工具可能自动展示过程版本，生成前须说明它们不是最终排序；修订时明确替换哪一页，不承诺脚本能隐藏工具消息。只要方案或比较候选风格时不强制打包。

历史第01款提示词与补正见 [AI 工具示例](references/style-01-ai-tools.md)。它及仓库八张示例为3:4历史样例，不覆盖当前目标平台预设。

需要同主题的完整输出时，读取[两平台生成策略对照](references/multi-platform-example.md)：在相同3:4比例和09风格下，分别制定标题、信息密度和构图。该无人物示例以用户明确要求无人物为前提，不能用来取消Hresh封面人物要求，也不追加脸照问题。
